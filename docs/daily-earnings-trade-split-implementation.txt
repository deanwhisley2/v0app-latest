  Purpose: Builds a 30-day, 2-trades-per-day USD schedule from capital
  File:    lib/server/daily-two-trade-engine.ts

  Purpose: Pro-rates each user's % yield by how late they joined a session
  File:    lib/server/time-weighted-yield-engine.ts

Reserve schedule answers:  "How much USD is budgeted for this user this month,
                            split across morning/evening slots?"

Yield engine answers:      "What % (and USD) does this specific user earn on
                            their stake, given when they joined?"

At settlement, payout comes from the STORED join-time calculation
(expected_profit_usd), NOT a fresh recalculation.

LAYER 1 — DAILY TWO-TRADE ENGINE
================================================================================

File: lib/server/daily-two-trade-engine.ts

POLICY CONSTANTS (server-only, never exposed in customer UI)
  DAILY_RETURN_PCT_MIN      = 0.8      (~24% monthly if x 30)
  DAILY_RETURN_PCT_MAX      = 1.167    (~35% monthly if x 30)
  DAILY_TRADE_SPLIT_MIN     = 0.35     morning gets 35–65% of daily %
  DAILY_TRADE_SPLIT_MAX     = 0.65
  DAILY_TWO_TRADE_POLICY_DAYS = 30

Conceptual band was 21–28% monthly. Shipped code uses 0.8%–1.167% daily,
which over 30 days is roughly 24%–35% on capital — slightly wider, same order
of magnitude.

EXAMPLE: $100,000 capital
  At 0.8% daily   → $800/day   (two trades sum to $800)
  At 1.167% daily → $1,167/day
  Mid-band ~0.933% → ~$933/day (matches 700–933 table range when daily % varies)

FORMULAS IMPLEMENTED

1. Daily return % (deterministic "random-style" per day)
   dailyReturnPct = 0.8 + HMAC(scope, "daily_return_pct") x (1.167 - 0.8)
   Uses createHmac("sha256", TRADE_SESSION_RNG_SECRET)
   Same day always yields same %, not predictable from UI.

2. Two-trade split (morning + evening)
   morningShare     = 0.35 + HMAC(scope, "morning_share") x (0.65 - 0.35)
   eveningShare     = 1 - morningShare
   morningReturnPct = dailyReturnPct x morningShare
   eveningReturnPct = dailyReturnPct - morningReturnPct
   Conservation: morningReturnPct + eveningReturnPct = dailyReturnPct

3. USD per trade
   morningUsd = capital x (morningReturnPct / 100)
   eveningUsd = capital x (eveningReturnPct / 100)
   dailyUsd   = morningUsd + eveningUsd

4. Full 30-day schedule
   buildDailyTwoTradeSchedule(capitalUsd, periodKey)
   Loops days 0–29, keyed by "YYYY-MM|dN"
   Returns: { v: 2, source: "daily_two_trade_v1", days: [...] }

LAYER 2 — RESERVE LEDGER
================================================================================

File:     lib/server/trade-session-earnings-reserve.ts
Migration: supabase/migrations/20260703220000_trade_session_earnings_reserve_v1.sql

When a user first participates in a trade session for a calendar month:

1. ensureUserTradeSessionReserve() creates row in user_trade_session_earnings_reserves
2. Schedule built via buildDailyTwoTradeSchedule(capital, periodKey)
3. net_reserve_usd = sum of all 30 days x 2 slots (morning + evening USD)
4. Conservation: earned_usd + forfeited_usd + remaining_reserve_usd = net_reserve_usd

SLOT LOOKUP
  dayIndex = floor((sessionStart - monthStart) / 86400000)  capped 0–29
  slotGrossUsd = schedule.days[dayIndex].morningUsd OR eveningUsd

FORFEITURE
  If user with reserve misses a slot:
  forfeitMissedTradeSessionSlot() debits slot gross USD from remaining_reserve_usd
  Writes user_trade_session_slot_ledger with outcome: "forfeited"

LEGACY PATH (still in code, superseded for new reserves)
  Older reserves used TRADE_SESSION_MONTHLY_TARGET_PCT 27–30% with 3% platform fee.
  New reserves use daily_two_trade_v1 with monthly_target_pct: 0, no platform fee.

LAYER 3 — TIME-WEIGHTED YIELD ENGINE V2 (LATE-ENTRY RULE)
================================================================================

File:     lib/server/time-weighted-yield-engine.ts
Migration: supabase/migrations/20260608000000_time_weighted_yield_engine_v2.sql

CORE FORMULA

  durationHours      = (sessionEnd - sessionStart) / 3600000
  isEarlyBird        = joinTime <= sessionStart
  effectiveStart     = isEarlyBird ? sessionStart : joinTime
  remainingHours     = max(0, sessionEnd - effectiveStart)
  participationRatio = remainingHours / durationHours

  earnedPercent = isEarlyBird
    ? maxYieldPercent
    : participationRatio x maxYieldPercent

  profitUsd = capitalAtJoinUsd x earnedPercent / 100

EXAMPLE (your rule)
  0.6% over 8 hours, join 3 hours late → 5 hours remaining
  earnedPercent = (5 / 8) x 0.6 = 0.375%
  Tested in scripts/stress-test-yield-engine.ts

JOIN FLOW (locked at join, immutable at settlement)

  joinTradeSessionWithYieldEngine() called from activateTradeSessionBot()
  (lib/server/nexus-bot-session-service.ts)

  1. Admin registers session with max_yield_percent (admin UI default 3.5%, manual)
  2. User confirms stake → calculateTimeWeightedYield() runs ONCE
  3. Persisted to session_participant_profit_percentages:
       earned_percent, expected_profit_usd, participation_ratio,
       effective_start_time, is_early_bird
  4. Audit row in yield_calculation_audit with SHA-256 hash
  5. Idempotency via session_join_idempotency

SETTLEMENT (reads stored value only)

  settleTradeSessionParticipation() → getStoredYieldParticipant()
  Pays expected_profit_usd
  Legacy reserve-slot proportional math DISABLED (LEGACY_EARNINGS_DISABLED)

POSTGRES ADDITIONS
  trade_sessions.max_yield_percent
  trade_sessions.yield_distribution_mode = 'LINEAR_TIME_WEIGHTED'
  Extended session_participant_profit_percentages columns
  yield_calculation_audit table
  session_join_idempotency table
  View user_earnings_explanation_v1 with labels:
    EARLY_BIRD — Full max yield
    LATE_ENTRY — Time-pro-rated yield
    REJECTED — Joined after end
